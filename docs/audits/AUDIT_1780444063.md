## Reconciliation (spec↔code) — the substantive findings

### R1. [MEDIUM] `wgPubKeyOf(bytes32)` is declared on two facets in the spec (diamond selector collision)

`contracts.md` declares `wgPubKeyOf` on **both** `IAttest` (§5.1, line 194) and `INetwork` (§5.3, line 308). Two facets cannot register the same 4-byte selector in one diamond. **Code resolution**: registered on **NetworkFacet only** (the canonical `NetworkStorage` value); `AttestFacet` still *implements* it as a mirror but its selector is intentionally excluded from the cut (`ClusterCut.sol`), mirroring how the master spec already resolves the analogous `listMembers` clash (master §3.3). Documented in `ClusterCut.sol`. **Action**: update `contracts.md` to state `wgPubKeyOf` is served by NetworkFacet; AttestFacet's is an unregistered convenience mirror.

### R2. [MEDIUM] `_setWgPubKey` ownership is contradictory in the spec

`contracts.md` §5.1 (line 228) lists `_setWgPubKey` as **AttestFacet's** internal selector (mirror updater), but §6.3 step 9 (line 420) calls `INetwork(address(this))._setWgPubKey(...)` and §5.3 (line 317) says NetworkFacet calls `AttestFacet._setWgPubKey` for the mirror — the same selector cannot live on both facets. **Code resolution**: `NetworkFacet` owns `_setWgPubKey` (the canonical writer DstackFacet calls, matching §6.3 step 9); `AttestFacet` exposes `_setWgMirror` for the MemberStorage mirror. Net behaviour (canonical NetworkStorage + atomically-synced mirror) matches the spec's intent; only the AttestFacet selector name differs. **Action**: update `contracts.md` §5.1/§5.3 to rename AttestFacet's internal selector to `_setWgMirror`.

> R1 and R2 share a root cause: the contracts spec's literal ABI has selector collisions that surface only at diamond-cut time. The code is correct and necessary; the spec needs the same de-collision notes it already applies to `listMembers`.

### R3. [LOW] `DiamondInit.InitArgs` gained a `memberFactory` field not in spec §8

DstackFacet's registration step 1 (`isOurMember`, mandated by contracts §6.3) needs the canonical `ClusterMemberFactory` address on chain. The master spec §9 lists "Member factory address" as cluster-owner config, so the code adds `memberFactory` to `InitArgs` + `MemberStorage` + the deploy JSON. **Action**: add `memberFactory` to `contracts.md` §8 `InitArgs`.

### R4. [LOW] `DstackFacet.owner()` is not registered on the diamond

Spec §6.1 lists `owner()` on DstackFacet returning the cluster owner, but the diamond's SolidState `SafeOwnable` already owns the `owner()` selector. Code leaves `owner()` to SafeOwnable (the solidstate owner), which equals the cluster owner in the common single-Safe deployment; they can diverge only if an operator intentionally splits the two roles. Documented in `ClusterCut.sol`. **Action**: note this in `contracts.md` §6.1.

### R5. [LOW] `ClusterDiamondFactory.predictClusterAddress` is approximate

It hashes the CREATE2 init code with empty `initCalldata`, so it does not exactly predict the deployed cluster address (which embeds the real `InitArgs`). Not used by the v1 demo path (members are predicted, clusters are deployed-then-read). Documented inline. **Action**: either compute with the real args or mark the helper non-authoritative in the spec.

## Known gaps — deferred BY the specs (not defects)

- **End-to-end integration harnesses are `#[ignore]`d stubs** (sidecar §16.2, indexer §14.2). Both specs scope these to the milestone-A demo (they need anvil + a live dstack socket + multi-process wireguard). The v1 deliverable is the component unit suites, which are complete and green.
- **Wireguard** is behind a swappable `MeshControl` trait (command impl + mock) rather than `defguard_wireguard_rs` netlink (sidecar §2.1). Lets the crate build/test without a kernel; full mesh bring-up is not exercised here. Drop-in replaceable.
- **dstack runtime** is a vendored trait + `MockDstack` (the spec sanctions "vendored if not crates.io-published"); the production UDS client is best-effort and unexercised.
- **Rust→chain registration submit path** (UserOp → bundler → `dstack_register`) is structural — it needs anvil + a KMS-chain source. The on-chain verification side is fully tested via the Solidity `MockKmsChain` (incl. real secp256k1 decompression), and `bind_hash` is cross-checked against Solidity.
- **Indexer** (agent-reported, documented inline): single chain-ordered fan-out vs per-cluster tasks; backpressure "drop-oldest" approximated via gap-signal + cursor replay; subscribe-time membership via the `MemberRegistered` cache with the synchronous `AttestFacet.memberOf` fallback present but unwired.
