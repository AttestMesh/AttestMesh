Premortem — Deploying the AttestMesh v1 Cluster

Frame: it's a few weeks from now. We deployed the three-node demo on Base Sepolia and it failed. This is why it died.

Verdict — not a risk profile, a certainty: ≥4 independent guaranteed showstoppers
What
The AttestMesh v1 three-node demo on Base Sepolia (master §11): infra → Indexer → gas-webhook/paymaster → ClusterDiamond → 3 ClusterMembers → 3 dstack CVMs that register, mesh, distribute the CSK, and go healthy.
Who
The AttestMesh org (infra + Indexer + paymaster) and three node operators. This demo is the end-to-end proof.
Success
All 3 register on chain, the wireguard mesh converges, the CSK reaches all 3, every healthcheck returns 200, app containers start.
Investigation
7 parallel deep-dive agents, each grounded in the actual repository code. Today: 2026-06-03.

Synthesis — read this first

Most likely failure

The first real-world boundary the sidecar touches — the dstack guest agent — rejects it at boot (F4).

Chronologically the earliest fatal seam. UnixSocketDstack POSTs hand-guessed routes (/DeriveKey, /Seal) with a confused {"path","purpose"} body; the real dstack agent speaks Tappd/prpc and may not even expose seal/unseal. derive_key fails → no keys → boot aborts before anything else can run. But "most likely" undersells it: F1, F2, F4, and F5 are each ~100% to fire on first contact with the real world. The honest probability that the demo works as-built is ≈0.

Most dangerous failure

Silent, irreversible CSK loss (F4 insidious branch / F6 originator race).

If derive_key happens to return 32 decodable bytes, the originator commits an immutable keccak256(CSK) on chain — but if seal/unseal don't truly round-trip (or the originator races/crashes), the CSK is gone forever after the first restart, with the commitment permanently fixed. The cluster bricks after appearing to pass. Unrecoverable beats merely-broken.

The hidden assumption

"147 green unit tests" was equated with "it works."

Every test runs against a mock or stub at exactly the four places the system meets reality — the dstack runtime, the dstack KMS proof the on-chain verifier checks, the Alchemy bundler/paymaster, and the live Indexer→sidecar event wire. The mocks were authored alongside the code they validate, so they encode the same assumptions and cannot catch a wrong belief about an external contract. The test suite is green precisely where confidence is least earned.

The revised plan — don't deploy the demo yet; climb the validation ladder first

  1. Treat the current build as a spec-faithful prototype, not a deployable artifact. Cancel the 3-node Sepolia demo until the four real-world seams are validated in isolation.
  2. dstack runtime (F4): stand up one real dstack CVM, curl --unix-socket the guest agent, capture the true derive_key/get_quote/seal API, and rewrite UnixSocketDstack against it. If seal/unseal don't exist, redesign CSK persistence before anything commits a commitment on chain.
  3. dstack KMS verifier (F1): capture one real DstackProof from that CVM and add a forge fork-test replaying it against the deployed DstackFacet. Fix the preimages/key-encoding until a real proof verifies — not the mock.
  4. EIP-4337 (F2): reorder bundler.rs::submit to request paymaster sponsorship first, then compute the userOpHash and sign — and land one real sponsored registration UserOp on Sepolia before scaling to three.
  5. Indexer wire (F5): implement the RLP event_data decode + dispatch in indexer_client::connect_and_run (it is currently a tracing::debug! no-op), and add the §16.2 anvil test asserting A's PeerEndpoint becomes a configured wg peer on B.
  6. wireguard (F3): confirm the CVM image ships the wireguard module + iproute2 + NET_ADMIN; remove the .ok() on create_interface so a missing mesh fails loud instead of marching into a doomed heartbeat phase.
  7. timing/originator (F6): make originator selection robust to the memberCount() race (derive it from MemberRegistered block+logIndex ordering, not a post-hoc read) and rehearse the 3-node bring-up on local anvil + 3 sidecars before Sepolia.
  8. diagnostics (F7): add per-phase health detail so a stuck node reports which dependency it's blocked on, and write a one-page deploy runbook + smoke test that exercises every seam.

Pre-deploy checklist — verify each before touching the Sepolia demo

  • ☐ A forge fork-test replays a real recorded dstack proof against the deployed DstackFacet and passes (F1).
  • ☐ One real, paymaster-sponsored registration UserOp lands on Sepolia and emits MemberRegistered — proving F2 + F1 + webhook + paymaster funding together.
  • ☐ ip link show attestmesh0 shows an up interface inside the actual dstack CVM image, and a wg handshake completes between two CVMs (F3).
  • ☐ An integration test asserts A's PeerEndpoint → B configures a wg peer — i.e. the Indexer decode wire is connected (F5).
  • ☐ The 3-node bring-up reaches all-healthy at least once on a local anvil + sidecar harness, with the CSK pulled by both onboardees (F4/F6).

The seven failure modes

F1 · On-chain dstack verifier was built against a mock KMS chain

Certain
Real dstack KMS returns a TDX quote + cert chain over its own canonical preimages/encodings — not the hand-authored ecrecover chain over abi.encode("dstack.app",…) the verifier checks. dstack_register reverts KmsAppKeySigInvalid on every node; _addMember never runs; the cluster is born empty. The sidecar retries 10× and exits non-zero.
Underlying assumption
Real dstack KMS output is shaped exactly like the hand-authored mock (ecrecover-able secp256k1 over AttestMesh-chosen preimages), not a TDX quote over dstack's own encodings.
Early warning signs
A fork-test replaying one real recorded proof reverts; compressedToAddress(kms_root_pubkey) isn't in allowedKmsRoots on the first real socket call.

F2 · EIP-4337 signature dies once Alchemy inserts paymaster data

Certain
bundler.rs::submit computes and signs the userOpHash while paymaster==None. Alchemy fills paymasterAndData after the webhook approves; the EntryPoint then recomputes the hash over the populated field, validateUserOp recovers a different signer, returns SIG_VALIDATION_FAILED, and every registration op reverts (AA24). The sidecar treats it as a transient "webhook declined" and retries forever.
Underlying assumption
A signature computed before paymasterAndData is populated still validates afterward — i.e. the v0.7 userOpHash is stable across the paymaster handshake.
Early warning signs
AA24 signature error on every registration; no test asserts user_op_hash equality between a paymaster=None op and the same op with paymaster fields filled.

F3 · Wireguard never establishes on the real CVMs

High
CommandWg::create_interface runs ip link add … type wireguard; the CVM image lacks the module/iproute2/NET_ADMIN, so it fails — but create_interface(…).ok() in state::run swallows it and boot marches into Heartbeating. Packets to the mesh /32s drop at the host, is_converged never latches, healthcheck stays 503 forever.
Underlying assumption
A MeshControl that passed only against MockWg behaves the same on a real kernel — and would fail loud, not be swallowed by .ok().
Early warning signs
Every node sits in Heartbeating with zero received heartbeats; ip link show attestmesh0 says "device does not exist" despite a clean boot log.

F4 · The dstack runtime client is a guessed UDS stub

Certain
UnixSocketDstack POSTs /DeriveKey with {"path","purpose"}; the real agent speaks Tappd/prpc and returns a keypair/cert, not {"key":"0x…"}. Node 1 dies at boot (missing key / malformed dstack response). Insidious branch: if it half-works, seal/unseal (which real dstack may not expose) silently no-op and the CSK is unrecoverable after restart — with its commitment already immutable on chain.
Underlying assumption
A reverse-engineered guess at dstack's paths, JSON shapes, and primitive set (incl. a seal/unseal that may not exist) equals the real protocol because the mock round-tripped.
Early warning signs
No test ever instantiates UnixSocketDstack; a curl --unix-socket against a real CVM 404s /DeriveKey//Seal.

F5 · Sidecar verifies Indexer pushes but never decodes/acts on them

Certain
Registration succeeds, the gRPC stream is up, every signature verifies, logs scroll verified indexer push — yet connect_and_run ends at tracing::debug! + let _ = &shared;. The RLP event_data decode/dispatch is a TODO, so MessageSent is never turned into a PeerEndpoint and wg::add_peer is never called. ListPeers stays empty: three nodes that see the chain but not each other.
Underlying assumption
"Signature-verified and logged" was tacitly equated with "consumed and acted upon," so a healthy stream was assumed to mean a converging mesh.
Early warning signs
add_peer / handshake counters stay at zero while verified indexer push climbs; no test drives connect_and_run across the gRPC boundary.

F6 · Convergence + CSK distribution deadlock under real async timing

High
Two nodes read memberCount() in the same block before either tx confirms — both see 0, neither becomes originator, the CSK is never derived, all sit at pulling-csk forever. Even when one does win, the strict active == live gate never latches across staggered boots: the window slides faster than the last node joins, so the three views are never simultaneously equal.
Underlying assumption
A system validated only against a synchronized logical clock with all peers present at t=0 behaves identically when three real nodes boot, register, and tunnel at independent wall-clock times.
Early warning signs
Two+ nodes log the originator read before any MemberRegistered confirms (cskCommitment() stays 0x0); is_converged flaps false, differing by exactly the last-joined node each tick.

F7 · Never integration-tested; every dependency a fail-closed SPOF

High
Three sidecars wedge in different phases — A pre-registration (webhook denial), B subscribed-but-empty (registry/cert mismatch), C waiting on B's peer signal — each silently at 503 with no signal of which dependency it's blocked on, no cross-node correlation, no orchestrator. The §16.2/§14.2 harnesses are #[ignore]d; the first time the processes talk for real is in front of the audience.
Underlying assumption
Components that each pass their own unit tests compose correctly across their seams on first contact, so end-to-end testing is a formality.
Early warning signs
CI has never produced a passing multi-process / anvil-backed run; the four components were authored by different agents with no shared seam contract or interop test.
